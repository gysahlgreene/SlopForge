## Confirmed gaps and proposed priority

1. **P0 — #9: establish one useful sprite workflow.** Test a pose/reference-controlled workflow and background isolation end-to-end on H100; acceptance should require visibly distinct frames, consistent identity, usable alpha, and deterministic package metadata. Current Wan samples do not meet that bar.
2. **P0 — #14: qualify one rigging route on a representative character.** Keep provider execution isolated. A pass must include valid topology/weights, visible deformation review, and export; model generation resolution is not topology QA.
3. **P1 — #20 workflow dependency manifests.** This audit adds graph-content hashes to new inference metadata and a workflow inventory. Remaining reproducibility gap: manifests do not pin custom-node revisions or hash model weights, and doctor cannot explain those mismatches. Build a small sidecar contract only with exact node/model declarations and checkable upstream identifiers.
4. **P1 — #15: repair Humanoid mapping or explicitly qualify Generic delivery.** Preserve the failed Unity evidence; test on representative rig data before closing.
5. **P2 — #16: concept-aware plan generation.** Reuse current plan/recipe machinery; require explicit review before cost-bearing execution.

The next implementation should stay with **#9**, because one reviewed sprite pack is a prerequisite for credible 2D character content and a small H100 experiment can resolve the known blocker. Do not advance #14 by installing an unverified node stack into production ComfyUI.

## Scope and limitations of this audit

The H100 smoke proved one two-icon recipe path and HTTP output retrieval. It did not test local ComfyUI, live reference conditioning, the full Wan sprite workflow, Unity interaction during this audit, or a fresh TRELLIS inference. Previous H100, Blender, and Unity evidence is explicitly marked above and in its issue documentation. No 1536³ run was performed. Model weights and the H100's ComfyUI environment were not modified.
