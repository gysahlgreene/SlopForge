This audit follows the 3D-only migration and reviewed Basalt rig. It covers repository structure, public documentation, production modules and helper boundaries, tests, packaging, open issues, and sensitive-data publication. The [October 4 audit](archive/release-audit-2026-10-04.md) remains historical context.

## Sensitive-data findings

- The initial audit checked 451 tracked files and all 73 then-reachable commits / 773 distinct Git blobs with targeted credential patterns. Git remote URLs contained no embedded credentials.
- Gitleaks 8.30.1 scanned all reachable refs. Its six generic-key findings were verified as labeled public SkinTokens revisions/checkpoint hashes, not credentials. A narrow provenance allowlist produces a clean scan while keeping the default credential rules enabled.
- GitHub reported zero open secret-scanning alerts. Secret scanning and push protection are enabled.
- Private ComfyUI addresses and personal absolute paths were present in public documentation, reports and 15 PNG metadata records. They were redacted from the active tree. PNG compressed pixel chunks are unchanged; [source/published hashes](media/publication-sanitization.json) record the metadata-only changes. **Earlier commits still contain that metadata.** One older [issue #5 verification comment](https://github.com/gysahlgreene/SlopForge/issues/5#issuecomment-5978193984) also retains a private service address, without a credential. No public history or tracker comments were rewritten; downloaded copies cannot be recalled.
- Extracted text metadata from 83 PNG/GIF images and public issue bodies/comments were also scanned with no credentials detected. Other binary contents, unreachable objects and external clones were not comprehensively scanned. “No credentials detected” is the supported conclusion, not an absolute guarantee.

See [publishing guidance](../SECURITY.md). Reports should retain model/source hashes and measurements, without private host details or personal paths.

## Remaining code risk

Texture approval still trusts previously recorded candidate validation rather than re-inspecting or checking complete output hashes immediately before publication. External changes to candidate bytes can invalidate that evidence. Publication rollback now protects previous files on ordinary errors, but it does not solve stale qualification or process interruption. Add candidate-integrity checks and crash-safe replacement as part of the delivery contract before claiming deterministic, fully transactional reimport.
