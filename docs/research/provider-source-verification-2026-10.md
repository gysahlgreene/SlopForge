# SlopForge provider research verification

**Checked:** 2026-10-04. This verifies selected claims in `docs/research/game-asset-pipeline-2026.md` against first-party repositories, official model cards, and official ComfyUI documentation. Repository documentation is evidence of what its authors state, not independent validation of quality or licensing of training data. This is research input, not a product specification or legal opinion.

## Findings

### Rigging: SkinTokens, UniRig, and ComfyUI-UniRig

- **SkinTokens is officially described as UniRig’s successor**, and its project/model pages describe one model generating skeleton plus skin weights. Its README says NVIDIA GPU with **at least 14 GB**, Python ≥3.11, CUDA Toolkit ≥12.1; code license is MIT. HF model card also labels the checkpoints MIT and names the recommended checkpoint. These are upstream requirements/labels, not an independently tested H100 result: [SkinTokens README](https://github.com/VAST-AI-Research/SkinTokens), [SkinTokens model card](https://huggingface.co/VAST-AI/SkinTokens).
- **Material caveat for commercial use:** SkinTokens says its recommended checkpoint trained on ArticulationXL 2.0, VRoid Hub, and ModelsResource, while the training data splits are not yet released. The repo/model-card MIT labels do not independently establish rights for those source datasets or settle output provenance. The 14 GB claim is inference memory stated by the authors; I found no official Mac/Apple Silicon support claim. Treat it as an isolated experimental provider pending SlopForge quality, compatibility, and data-rights review—not as a proven production default.
- **UniRig code and HF checkpoint are labelled MIT**, and upstream README says Python 3.11/PyTorch ≥2.3.1 with `spconv`, PyG and flash-attn dependencies. However, HF describes its hosted checkpoint as the skeleton prediction component and says other/full checkpoints are future releases; its stated GPU floor is >8 GB. No official minimum for a complete rigging run was found. This makes UniRig a potentially useful baseline, but “fallback” should not imply a complete, currently supported equivalent pipeline. Sources: [UniRig repository](https://github.com/VAST-AI-Research/UniRig), [UniRig model card](https://huggingface.co/VAST-AI/UniRig).
- **ComfyUI-UniRig’s wrapper repository is GPL-3.0** and README says it bundles UniRig/MIA/Blender code. It supports UniRig or MIA; it is not an upstream SkinTokens integration. README warns that its one-click install uses experimental `comfy-env` and Pixi; manual instructions run `pip install -r requirements.txt --upgrade` and `python install.py`. The requirements currently name `comfy-env==0.4.1`; install.py calls its installer. These facts support isolating it from production ComfyUI. GPL-3.0 alone does not prohibit commercial use, but distribution obligations and the separate licenses of bundled code, models and dependencies need review. The repository documents ComfyUI nodes/workflows, but no compatibility matrix or tested API-format workflow was found. Sources: [ComfyUI-UniRig README](https://github.com/PozzettiAndrea/ComfyUI-UniRig/blob/main/README.md), [requirements](https://github.com/PozzettiAndrea/ComfyUI-UniRig/blob/main/requirements.txt), [installer](https://github.com/PozzettiAndrea/ComfyUI-UniRig/blob/main/install.py), [license](https://github.com/PozzettiAndrea/ComfyUI-UniRig/blob/main/LICENSE).
- **Recommendation adjustment:** upstream SkinTokens merits an isolated evaluation first because it is the authors’ successor and the documented workflow is simpler; available sources do not justify calling it SlopForge’s default yet. Do not position UniRig as a dependable fallback without validating current checkpoint coverage and end-to-end rigging. ComfyUI-UniRig remains optional and uninstalled pending dependency and workflow tests. None of these sources establishes good deformation on SlopForge’s generated meshes.

### MIA / Hunyuan3D license restriction

- The report’s EU warning is supported for **Tencent Hunyuan3D 2.1**: its license explicitly says it does not apply in the EU, UK, or South Korea and limits the territory accordingly. This is a material blocker for Ireland. Source: [official Hunyuan3D-2.1 license](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/LICENSE).
- Be precise about which asset is licensed: Make-It-Animatable’s **code repository is MIT**, while its HF model card labels the model `apache-2.0`; MIA v2 README says it uses Hunyuan3D 2.1 ShapeVAE. These are distinct layers, and do not erase Hunyuan’s restriction for that upstream component. Sources: [MIA repository](https://github.com/jasongzy/Make-It-Animatable), [MIA model card](https://huggingface.co/jasongzy/Make-It-Animatable).

### TRELLIS.2

- Upstream currently documents **Linux-only tested**, NVIDIA GPU with **at least 24 GB**, and verification on A100/H100; it lists 512³–1536³ and reports H100 timing. Its official repository and HF model card label code/model MIT. Sources: [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2), [TRELLIS.2 model card](https://huggingface.co/microsoft/TRELLIS.2-4B).
- Important quality limitation: the authors explicitly advertise support for **open surfaces and non-manifold geometry**. 512³–1536³ is a generation-resolution capability, not a guarantee of closed, riggable, game-ready character topology. The research report should not imply TRELLIS is a character mesh/rigging-ready provider without deterministic mesh QA and real deformation checks. This matches the H100 test failures already recorded in SlopForge evidence.

### Wan 2.2

- Official code license is Apache-2.0, and the official HF I2V-A14B and TI2V-5B cards also state Apache-2.0. The official repo says TI2V-5B is 720p/24 fps and can run on a single consumer GPU such as 4090; its T2V-A14B single-GPU command is documented as requiring at least 80 GB, with offload/dtype options for OOM. Sources: [Wan2.2 repository](https://github.com/Wan-Video/Wan2.2), [I2V-A14B model card](https://huggingface.co/Wan-AI/Wan2.2-I2V-A14B), [TI2V-5B model card](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B).
- Upstream README confirms ComfyUI integration for Wan2.2. This verifies support exists, but not every variant/workflow, third-party wrapper, or transparent sprite output. The earlier SlopForge Wan sample test found its chosen I2V path nearly static and opaque; that local integration result should remain the qualification for the sprite use case.

### BiRefNet, DWPose, OpenPose, ComfyUI

- BiRefNet upstream code repo is MIT and documents official ComfyUI integration. I did not verify the exact license for each downloadable checkpoint used by SlopForge, so phrase “MIT weights” only if the specific weight artifact’s license is confirmed. Sources: [BiRefNet repository](https://github.com/ZhengPeng7/BiRefNet), [ComfyUI official BiRefNet integration](https://blog.comfy.org/i/197285326/birefnet-high-resolution-background-and-object-segmentation).
- DWPose repository license is Apache-2.0. This verifies repository code terms; associated model checkpoints and dependencies should still be individually checked before redistribution. Source: [DWPose repository](https://github.com/IDEA-Research/DWPose).
- OpenPose’s official README/license explicitly limits free use to non-commercial use and links commercial licensing. The report’s caution is correct. Sources: [OpenPose README](https://github.com/CMU-Perceptual-Computing-Lab/openpose#license), [OpenPose license](https://github.com/CMU-Perceptual-Computing-Lab/openpose/blob/master/LICENSE).
- Current ComfyUI upstream describes reusable workflows and API integration. That supports treating ComfyUI as an execution backend, but says nothing about compatibility of arbitrary custom nodes; preflight and API workflow testing remain necessary. Source: [ComfyUI repository](https://github.com/comfyanonymous/ComfyUI).

## Verification gaps / edits recommended for the research report

1. Replace unconditional “SkinTokens primary rigging provider / Must-have” with “best first isolated candidate to evaluate; not yet production-qualified.” Explicitly record that training data splits are not yet released and source-data rights were not verified.
2. Qualify UniRig fallback: upstream releases and checkpoint coverage are incomplete/ambiguous, and no full-stack VRAM floor is stated.
3. State that ComfyUI-UniRig is a GPL-3 wrapper with experimental install tooling, separate component/model terms, and no verified SkinTokens node or API workflow. Do not describe GPL as itself non-commercial.
4. Do not present TRELLIS resolution support as suitability for animation-ready characters; upstream explicitly permits open/non-manifold output.
5. Distinguish source-code license from weight/checkpoint license for BiRefNet, MIA, and all providers; record the exact model artifact’s license.
6. The broad “commercial” conclusions remain limited by training dataset and third-party dependency/model terms. Have counsel review before redistributing bundled software or model assets.
